# Live Import Lanes

This directory defines the demo-path import lanes.

- `reference.json` pulls shared reference contracts (including channel rollups). It also pulls sheet **402** tabs **Seed Sources** and **Seed Order** from the same workbook as Crop Planner (`1jFhWod…`) into `reference/seed_sources.csv` and `reference/seed_orders.csv` (Stage A2 / `pull_stage_a2_bundle` only — no local CSV overlay). On disk the lane root is `live_import_bundle/reference/` and canonical CSVs live one level deeper in `live_import_bundle/reference/reference/`; **`import_reference_data`** accepts that layout (same as **`import_historical_data`**’s `reference/` resolution).
- `crop-plan.json` pulls operator crop-plan lanes (`plantings.csv`, `nursery_events.csv`). **`live_import_bundle/` is not a deploy artifact** — it is whatever directory `pull_stage_a2_bundle` (via `make live-import-*` or the cloud pull job) just wrote. **`PlanningYear` rows** come from `year_<Y>/planning_year.csv`. The pull step **creates that file when it is missing** for each calendar year in the run (default `Year,Status,Overplant Factor` → `<Y>,planning,1.10`) so local SQLite and Cloud SQL apply behave the same without checking bundle CSVs into git. Override by placing your own `planning_year.csv` under `year_<Y>/` before import, or edit status/overplant after pull. Older commits may still show hand-maintained `planning_year.csv` files under `crop-plan/` for fixtures; they are optional once pull auto-seeds.
- `sales-plan.json` pulls workbook **Sales Plan 302** into `year_YYYY/sales_plan_302.csv`. Rows are **filtered by the Harvest Year column** so each `year_YYYY/` file only contains lines for that calendar year (the same tab is fetched per year). Run `live-import-crop-plan` before sales-plan so `PlanningYear` rows exist for each year in range (pull now seeds missing years; reference import does not create planning years by itself). If Sales Plan names a product that is still missing from **Farm Crop Formats** but the **Crop Info** prefix matches (e.g. `Cucumber Persian - lb` after crop `Cucumber Persian` exists), `import_historical_data` may **auto-create** a minimal `CropSalesFormat` during apply (see importer warning line); prefer adding the row on the formats sheet so price/SKU stay authoritative.
- `historical-601.json` pulls **`601 Field Walk & Weekly Sales Plan LSF YYYY`** from the crops parent folder on Drive (`drive_folder_id` in the JSON). Each calendar year must be a spreadsheet whose **exact title** matches that pattern (with `YYYY`). Tabs **`Market`**, **`Orders`**, and **`Build Crop Mix`** normalize to `year_YYYY/sales_events.csv` and `year_YYYY/pack_batch_components.csv`. Tabs **`Crop Info`** and **`Farm Crop Formats`** (same column contracts as `reference.json`) write to **`year_YYYY/reference/crop_info.csv`** and **`year_YYYY/reference/crop_sales_formats.csv`** so each season’s workbook can carry its own catalog and prices. After **`scripts/farm_cloud_pull.sh`** finishes all lanes, it runs **`build_reference_superset`**, which merges those per-year files into **`live_import_bundle/reference/reference/crop_info.csv`** and **`crop_sales_formats.csv`** (with **`Planning Year`** on format rows) before you run **`import_historical_data`** on the reference lane. To re-merge without re-pulling Drive, use **`scripts/run_import.sh reference-superset`** (local). **`make live-import-reference`** runs the same merge after its reference pull (using any **`historical-601`** year folders already under the bundle). **Apply** the 601 lane with **`import_historical_data`** only **after** reference (and usually crop-plan / sales-plan) so channels, products, and planning years already exist in the database. Configured years are **2023–2025**; cloud **`import_historical_data`** in **`farm-backfill`** still uses **`CLOUD_RUN_IMPORT_START_YEAR`/`CLOUD_RUN_IMPORT_END_YEAR`** (default **2024–2026**), so set **`CLOUD_RUN_IMPORT_START_YEAR=2023`** (and an appropriate end year) on the backfill job if you need **2023** rows applied in Cloud SQL.

**Recommended order on a fresh database:** `make live-import-reference` (or `make import-reference` / `import_reference_data`), then `make live-import-crop-plan`, then `make live-import-sales-plan`, then pull/apply the 601 lane (same `pull_stage_a2_bundle` + `import_historical_data` pattern as other lanes; see `scripts/farm_cloud_pull.sh` / cloud **`farm-backfill`** which runs all four lanes in order).

Run lanes locally:

- `make live-import-reference`
- `make live-import-crop-plan`
- `make live-import-sales-plan`
- `make live-import-all` (reference → crop-plan → sales-plan)

Validation (no network):

- `make live-import-validate`

Engineering rehearsal configs under `docs/live-rehearsal-*.example.json` remain available but are not on the demo path.
